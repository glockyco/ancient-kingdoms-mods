## Why

The compendium publishes what the game contains but cannot answer the question players actually
ask: which gear, attributes, and skill levels produce the most output against a chosen target. The
deterministic rules come from decompiled server code. Serialized prefab values come from exports, and
ambiguous runtime behavior comes from repeatable measurements. Together these sources make a
reproducible model possible without Monte Carlo ranking or fitted stat weights.

## What Changes

- Add a deterministic combat evaluation model derived from the decompiled server source. The model
  computes sustained damage per second from a character state and a target parameter set. It
  reproduces the damage pipeline, the avoidance and mitigation terms, the resource engine, buff
  uptime, and a solved rotation.
- Add a constrained optimizer over three coupled dimensions: equipment across 16 slots, attribute
  point allocation, and normal and veteran skill point allocation. The optimizer enumerates the
  discrete weapon and hand branches, then runs multi-start block coordinate ascent inside each
  branch. Weapon choice and rotation are constrained jointly, because a damaging skill can require a
  weapon category.
- Optimize the equipment of each active mercenary as well as the player. A mercenary's equipment
  component inherits the player equipment stat pipeline, so mercenary gear contributes its full stat
  set and not attributes alone. A solo player with four mercenaries therefore has 64 further
  equipment decisions that change total output.
- Add a planner page that renders a default build and its numbers in prerendered HTML. Interactive
  controls edit class, progression, equipment, attributes, skills, consumables, mercenaries, target,
  and scenario. Optimization runs through a dedicated compute worker.
- Add a compact planner payload generated by the build pipeline. It carries equipment, class and
  race progression, skill trees, mercenary archetypes, consumables, and every output effect the model
  must classify. The measured equipment subset is 21 KB gzipped for 887 equippable non-costume items.
- Add a player-facing mod that writes live character and controlled-entity state to one versioned
  local JSON file. The planner imports that file locally. A separate explicit command resets the
  game's combat meter, and a read-only capture records its output for comparison.
- Select the level 55 training dummy in Northern Wastes as the default target. Its `damage` value is
  0, so the default experience needs no survivability, threat, or healing model. Record that the same
  property makes the dummy understate a build that depends on taking damage.
- Model the resource-burn skills, which convert the whole current resource pool into damage that
  ignores both avoidance and mitigation. Against a high-mitigation target this makes maximum resource
  a damage stat rather than a rotation enabler.
- Model declared consumable buffs and ammunition inside an explicit evaluation scenario. The
  scenario also fixes fight duration, starting state, incoming damage, included entities, and the
  single-target boundary, so a published result has no hidden encounter assumptions.

Non-goals for this change, recorded so later work does not treat them as omissions:

- Party composition support profiles, survivability feasibility, and defensive optimization. This
  excludes buffs and debuffs an ally applies. It does not exclude a mercenary's own output.
- Modelling another player's build or play quality. This change optimizes the player and active
  mercenaries. It captures pets for provenance and meter accounting but does not optimize pet builds.
- An in-game optimizer, an action priority list interpreter, or any mod that casts or queues an
  action.
- User-facing stat weights. Measurement showed that a single local gradient misranks builds.
- Mechanics that cannot occur against the default target and are therefore deferred with the rest of
  the boss model: the enrage bonus below 50 percent health, the critical bonus for interrupting a
  cast, durability loss during a fight, and the slayer damage reduction.

## Capabilities

### New Capabilities

- `combat-model`: What the deterministic evaluation guarantees about the numbers it produces. Covers
  the damage pipeline, the resource engine, buff uptime derivation, the solved rotation, the target
  parameter set, and the boundary between computed values and stated assumptions.
- `build-optimizer`: What the search guarantees about the builds it returns. Covers the decision
  variables, the constraints it enforces, the branch enumeration it requires, the multi-start
  requirement, and the accuracy it claims.
- `gear-planner`: What the planner page guarantees to a reader. Covers the prerendered content, the
  no-JavaScript path, the shareable state, the encounter selection, and how uncertainty is
  presented.
- `character-state-export`: What the export guarantees about a captured character. Covers the payload
  contract, version and provenance markers, completeness reporting, and the measured combat-meter
  readout.

### Modified Capabilities

None. `skill-mechanics-card` constrains what a skill page displays about the damage pipeline. This
change adds an evaluation engine and does not change that display contract. `game-data-export` and
`compendium-build` gain a new derived artifact, which their existing requirements already cover. The
capture command joins the surface that `runtime-control` defines and has to satisfy its guarantees,
but it does not change them.

## Impact

- `build-pipeline/`: a new derived payload covering equippable items, per-class skill trees with
  their point costs and weapon gates, mercenary archetype data, and consumable buffs.
- `website/`: a new route, build editor, local capture importer, evaluation and optimization library,
  and dedicated compute worker. The database worker remains database-only.
- `mods/`: a distributable mod project for a local character-state file, a read-only meter capture,
  and an explicit meter-reset action. The shared capture core remains testable without the game.
- `citations.lock.json`: new source-cited constants for every formula the model reproduces.
- No change to the published database schema for existing entities.
