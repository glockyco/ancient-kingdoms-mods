## Why

The compendium publishes what the game contains but cannot answer the question players actually
ask: which gear, attributes, and skill levels produce the most output against a chosen target. The
deterministic rules come from decompiled server code. Serialized prefab values come from exports, and
ambiguous runtime behavior comes from repeatable measurements. Permanent learned books also change
progression, so the model must distinguish them from allocated points. Together these sources make a
reproducible model possible without Monte Carlo ranking or fitted stat weights.

## What Changes

- Add one production combat evaluator derived from the decompiled server source. It produces
  repeatable results for an explicit build and scenario. Its event timeline evaluates damage,
  resources, effects, and action gates from the state at each relevant event. Exact expectations
  require proof; other deterministic approximations require a stated scope and independent validation.
- Share logical build data through checked fixture, capture, and browser adapters. Declare stable
  learned-book asset IDs in `learnedBookIds`, and distinguish raw attributes, base or progression
  contributions, allocated points, and derived totals. Keep version identities, fixture execution data,
  and capture completeness and container metadata distinct. Empty learned-book state means none learned;
  missing or unread state is incomplete, and unknown or duplicate IDs are refused.
- Require complete running-game comparisons before marking predictions verified. Include learned-book
  gains in stat and damage parity, and require independently recorded read-only capture evidence for
  learned state. Preserve raw parity separately from evidenced known-defect-normalized results.
  Recommendations do not reward defect exploitation, and every comparison identifies which result mode
  it uses.
- State model accuracy, finite-run variance, and search quality separately. Numeric accuracy claims
  require an adequate current corpus and independent validation. Unverified domains carry no numeric
  accuracy boundary.
- Add a constrained optimizer over three coupled dimensions: equipment across 16 slots, attribute
  point allocation, and normal and veteran skill point allocation. Declared learned-book progression
  is fixed input, not a fourth allocation dimension, and the optimizer never silently grants books.
  The optimizer enumerates the discrete weapon and hand branches, then runs multi-start block
  coordinate ascent inside each branch. Weapon choice and rotation are constrained jointly, because a
  damaging skill can require a weapon category.
- Optimize the equipment of each active mercenary as well as the player. A mercenary's equipment
  component inherits the player equipment stat pipeline, so mercenary gear contributes its full stat
  set and not attributes alone. A solo player with four mercenaries therefore has 64 further
  equipment decisions that change total output.
- Add a planner page that renders a default build and its numbers in prerendered HTML. Interactive
  controls edit class, progression, learned-book declarations, equipment, attributes, skills,
  consumables, mercenaries, target, and scenario. The editor permits explicit hypothetical book
  declarations and preserves them in links and imports without changing the source capture or live
  character. Optimization runs through a dedicated compute worker.
- Add a compact planner payload generated by the build pipeline. It carries equipment, class and
  race progression, learned-book definitions from the required existing exported fields
  (`book_strength_gain`, `book_dexterity_gain`, `book_constitution_gain`, `book_intelligence_gain`,
  `book_wisdom_gain`, and `book_charisma_gain`), skill trees, mercenary archetypes, consumables, and
  every output effect the model must classify. Preflight refuses missing fields or unclassified
  effects, and publication remains deterministic and redacted. Remeasure the payload after adding
  the book domain instead of treating an older equipment-only measurement as book-inclusive.
- Add a player-facing mod that writes live character and controlled-entity state, including actual
  learned-book IDs, to one versioned local JSON file. Capture reads learned state rather than inventory
  ownership and never invokes learning, reset, or other mutation paths. The planner imports that file
  locally. A separate explicit command resets the game's combat meter, and a read-only capture records
  its output for comparison.
- Select the level 55 training dummy in Northern Wastes as the default target. Its `damage` value is
  0, so the default experience needs no survivability, threat, or healing model. Record that the same
  property makes the dummy understate a build that depends on taking damage.
- Model the resource-burn skills, which convert the whole current resource pool into damage that
  ignores both avoidance and mitigation. Against a high-mitigation target this makes maximum resource
  a damage stat rather than a rotation enabler.
- Model declared consumable buffs and ammunition inside an explicit evaluation scenario. The
  scenario also fixes fight duration, starting state, incoming damage, included entities, and the
  single-target boundary, so a published result has no hidden encounter assumptions.

Non-goals for this change, recorded so later work does not treat them as omissions:

- Party composition support profiles, survivability feasibility, and defensive optimization. This
  excludes buffs and debuffs an ally applies. It does not exclude a mercenary's own output.
- Modelling another player's build or play quality. This change optimizes the player and active
  mercenaries. It captures pets for provenance and meter accounting but does not optimize pet builds.
- An in-game optimizer, an action priority list interpreter, or any mod that casts or queues an
  action.
- User-facing stat weights. Measurement showed that a single local gradient misranks builds.
- Mechanics that cannot occur against the default target and are therefore deferred with the rest of
  the boss model: the enrage bonus below 50 percent health, the critical bonus for interrupting a
  cast, durability loss during a fight, and the slayer damage reduction.

## Capabilities

### New Capabilities

- `combat-model`: What the deterministic evaluation guarantees about the numbers it produces. Covers
  the damage pipeline, the resource engine, learned-book gain evaluation, buff uptime derivation,
  the solved rotation, the target parameter set, and the boundary between computed values and stated
  assumptions.
- `build-optimizer`: What the search guarantees about the builds it returns. Covers the decision
  variables, fixed learned-book progression, the constraints it enforces, the branch enumeration it
  requires, the multi-start requirement, and the accuracy it claims.
- `gear-planner`: What the planner page guarantees to a reader. Covers the prerendered content, the
  no-JavaScript path, the shareable state, the encounter selection, and how uncertainty is
  presented.
- `character-state-export`: What the export guarantees about a captured character. Covers the payload
  contract, version and provenance markers, completeness reporting, and the measured combat-meter
  readout.

### Modified Capabilities

None. `skill-mechanics-card` constrains what a skill page displays about the damage pipeline. This
change adds an evaluation engine and does not change that display contract. `game-data-export` and
`compendium-build` gain a new derived artifact, which their existing requirements already cover. The
capture command joins the surface that `runtime-control` defines and has to satisfy its guarantees,
but it does not change them.

## Impact

- `build-pipeline/`: a new derived payload covering equippable items, per-class skill trees with
  their point costs and weapon gates, mercenary archetype data, consumable buffs, and required
  learned-book definitions and effect classifications.
- `website/`: a new route, build editor with explicit hypothetical learned-book controls, local capture
  importer, evaluation and optimization library, and dedicated compute worker. The database worker
  remains database-only.
- `mods/`: a distributable mod project for a local character-state file with read-only learned-state
  capture, a read-only meter capture, and an explicit meter-reset action. The shared capture core
  remains testable without the game.
- `citations.lock.json`: new source-cited constants for every formula the model reproduces.
- No change to the published database schema for existing entities.
